## 🥇 高价值(优先做)

### H1 · 线稿模式(line-art mode)预处理

**对方实现**
对黑白线稿/动漫剪影风格的输入,先用 median filter 去除 JPEG/AA 灰噪,再做 NEAREST hard-edge 缩放到目标分辨率,最后走主色板匹配。两个关键点:
1. `median filter` 核大小是个参数(典型 3×3 或 5×5),目的是保留锐利边缘、平掉 AA 半透明像素。
2. NEAREST(非平滑)缩放避免重新引入灰阶过渡。

**借鉴理由**
当前 `pindou` 的两个像素化模式都是为「彩色插画/实景照片」设计的,遇到线稿(像素画师原稿、动漫图)时,AA 灰边会被当成主体色匹配进色板,得到一坨「中间色」而非黑/白/主色。这是个完全不同的输入场景。

**接入点**
- `public/js/generate.js`:加 `mode: 'lineart'` 分支,预处理流水线:`medianFilter → NEAREST → 主色板匹配 → 走现有 despeckle/merge`。
- `public/index.html` + `public/js/ui-mode.js`:「处理模式」下拉加第三项「线稿」。

**工作量**
- 算法:1 个新函数(`medianFilterRGB`)约 40–60 行,放在 `color.js` 或新建 `preprocess.js`。
- UI:2 处改动。
- 测试:合成几组线稿 fixture(纯黑线、红底白圆、蓝线等)验证去 AA 效果。
- 预计 1–2 个 task。

**风险**
- median filter 在 Canvas 像素访问层需要 ImageData 循环,大图(>1000px)性能需要抽查。
- NEAREST 缩放保留锐边但会丢失 1px 细节,需要文档化预期输出。

### H2 · 多板自动拼接 + 10×10 红定位线

**对方实现**
当目标图分辨率超过单板上限(58×58),自动切成 2×2 / 3×3 等子板,每子板独立可打印,板之间有重叠定位标记。每 10×10 格画一条红线,辅助实物拼装时定位行/列。

**借鉴理由**
实物拼豆是分板拼的。`pindou` 现在直接渲一张大 PNG,用户拿到打印件还要自己算该怎么分板。自动多板导出是「从虚拟图到实物拼装」的最后一公里 —— 体验质变。

**接入点**
- `public/js/generate.js` 或新建 `export-tiler.js`:参数 `boardSize`(默认 52 或 104)、`overlap`(默认 0)、`showGuideLines`(默认 true)。
- `public/js/ui-modals.js` / 导出对话框:加「是否分板」「板内尺寸」「重叠格数」「10×10 定位线开关」。
- 在「导出」按钮旁加新按钮「导出多板」,或合并进现有导出对话框。

**工作量**
- 模块:核心 tiling 逻辑约 100–150 行,涉及子图裁剪、标号、可选 overlap 复制。
- UI:导出对话框改造。
- 测试:不同 boardSize × 不同 grid size 的覆盖测试。
- 预计 3–5 个 task。

**风险**
- 现有「导出 PNG」是单图路径,多板会是平行路径,需要保持现有导出行为不变。
- 导出文件命名 / 数量管理需要 UI 约定(N 张 PNG vs 多页 PDF)。

### H3 · 8 邻去斑 + 2×2 细线保护

**对方实现**
8 邻投票去斑,但阈值调得保守 —— 只有当本格主色与邻居多数色差异足够大、且邻居中多数色形成「显著簇」时才替换本格外层色。专门保护 2×2 主体色块不被误判为噪声。

**借鉴理由**
`pindou` 现在 `despeckle`(4 邻 ≥ 3 一致即替换)在「主体色块 vs 噪声」时简单粗暴。借鉴 8 邻 + 簇大小检测可以让彩色插画里的细节线条、轮廓边保留得更自然,而不会因为 4 邻刚好是「噪声+背景」就误改。属于算法精度的微调,用户能感知但不是质变。

**接入点**
- `public/js/color.js`:改写 `despeckle` 函数,扩到 8 邻,加 `minClusterSize` 参数(默认 1,=1 等同现状;2 = 保护 ≥2 连通块)。
- `public/index.html`:高级设置里 despeckle 开关旁加一个细化强度下拉(简单 / 保护细线)。

**工作量**
- 算法:60–80 行,纯函数改动。
- UI:1 个下拉。
- 测试:合成线+主体色块的 fixture,确保不会误伤细线。
- 预计 1 个 task。

**风险**
- 需要保留旧 despeckle 行为作为回退(参数默认走老路径),避免破坏现有 51+ 测试用用例。

## 🥈 中等价值(挑空闲做)

### M1 · 导出层分离配置

**对方实现**
导出 PNG 时分别控制:背景透明 / 网格线 / 色号 / 统计行 / 字体大小 / cell size,每项独立 switch。

**借鉴理由**
`pindou` 的 `exportCanvas`(隐藏 canvas)已经做了层分离基础,但 UI 上用户不能选。可以更灵活地满足不同导出场景(打印纯图 / 带色号教程图 / 简洁统计表)。

**接入点**
- `public/js/ui-modals.js`:导出对话框列出复选框组。
- `public/js/generate.js` 或 `fused-preview.js`:导出函数接收 `layers` 选项对象,按需渲染 layer。

**工作量**
- 模块:导出函数参数化约 30 行。
- UI:复选框 4–5 个。
- 预计 1 个 task。

---

### M2 · 批量替换色号

**对方实现**
编辑器里选中源色号 + 目标色号,一键整图替换。

**借鉴理由**
单格点改的效率在「整图某个色号用错品牌映射」场景下太低。批量替换能让用户一次修正大量误判。

**接入点**
- `public/js/editor.js`:加 `bulkReplace(fromCode, toCode)` 函数,遍历 grid。
- `public/js/ui-modals.js`:在「单格改色」modal 加「批量替换」按钮 + 入口。
- `public/js/state.js` + 历史栈:支持撤销(沿用现有 undo 链路)。

**工作量**
- 模块:函数约 30 行。
- UI:1 个 modal。
- 预计 1 个 task。

---

### M3 · 色号-品牌目录化数据

**对方实现**
每品牌一个 JSON 文件(目录化),后端启动时扫描加载。

**借鉴理由**
虽然刚 refactor 到单品牌,但目录化解耦让未来扩展不破坏现有代码。

**接入点**
- `public/js/palettes.js`:如果当前是单文件嵌入,改为启动时 fetch JSON(`public/data/palettes/mard.json`)。

**工作量**
- 仅在需要扩展品牌时做。如果单品牌长期不动,跳过。

**风险**
- 引入 `fetch` 异步,需要保证启动时序不破坏现有依赖图(同步加载 → 异步的迁移成本)。

按业务影响/工作量比:

1. **H1 线稿模式** —— 1–2 task,覆盖全新输入场景,首选。

4. M1/M2 —— 锦上添花,看是否有用户反馈再说。
